## 2. How the commit is made

The coordinator makes it, once `project-manager` has confirmed in writing that every row of the table above is committed, with a
verdict wherever a review is named. The script below is extracted byte for byte from the parent's copy of this document into a folder
outside the repository, and its hash is checked first. Then, under Git Bash, at the repository's top:

1. **`bash c5_steps.sh before`.** On a clean tree at the parent, it checks that `src/`, `configs/`, `pyproject.toml` and `uv.lock` equal
   `7bd375f`'s and that all 21 paths exist. It then writes the manifest and checks it against git's own listing. It prints one line
   and stops on any failure.
2. **The commit.** Stage that one path, confirm that `git diff --cached --name-only` prints it alone, and commit with the coordinator's
   message.
3. **`bash c5_steps.sh after`.** It checks that the new commit has one parent, adds the manifest and nothing else, still equals `7bd375f`
   in code, and that the committed manifest names its parent and equals git's listing at the new commit. It prints one line.

```bash
#!/usr/bin/env bash
# The C-5 commit's checks and manifest. Usage, at the repository's top under Git Bash: bash c5_steps.sh before|after
set -euo pipefail
P1=7bd375f2bc2327c479b6c480990e3ba91b003101        # P-1's commit (17.8 addendum, condition 1)
MANIFEST=docs/decisions/C5_MANIFEST.md
FROZEN=(                                            # fold plan section 10, the anchor table
  docs/00_CHARTER.md
  docs/01_strategies/00_INDEX.md
  docs/01_strategies/S01_floor_pivot_rejection.md
  docs/01_strategies/S02_pivot_breakout_acceptance_retest.md
  docs/01_strategies/S03_market_structure_bos_choch.md
  docs/01_strategies/S04_supply_demand_zones.md
  docs/01_strategies/S05_zone_polarity_flip.md
  docs/01_strategies/S06_liquidity_sweep_reclaim.md
  docs/01_strategies/S07_anchored_vwap_pullback.md
  docs/01_strategies/S08_volume_profile_value_area.md
  docs/01_strategies/S09_utc_session_range_breakout.md
  docs/01_strategies/S10_volatility_compression_expansion.md
  docs/02_features/GATE_SPEC.md
  docs/02_features/STRATEGY_FEATURE_MATRIX.md
  docs/02_features/FEATURE_TRIAGE.md
  docs/02_features/DECISION_POINT_MAP.md
  docs/01_strategies/COST_AND_INSTRUMENT_2026-11-05.md
  docs/decisions/FOLD_PLAN_2026-11-05.md
  configs/pipeline.toml
  configs/engine.toml
  docs/04_PORTFOLIO_OUTPUTS.md
)
listing() { git ls-tree "$1" -- configs pyproject.toml src tests uv.lock; git ls-tree -r "$1" -- "${FROZEN[@]}"; }
block() { sed -n '/^```text$/,/^```$/p' | sed '1d;$d'; }
same_code() { for p in src configs pyproject.toml uv.lock; do test "$(git rev-parse "$1:$p")" = "$(git rev-parse "$P1:$p")"; done; }
tests_same() { [ "$(git rev-parse "$1:tests")" = "$(git rev-parse "$P1:tests")" ] && echo yes || echo no; }
case "${1:-}" in
  before)
    P="$(git rev-parse HEAD)"
    test -z "$(git status --porcelain --untracked-files=no)"
    test ! -e "$MANIFEST"
    same_code "$P"
    test "$(git ls-tree -r --name-only "$P" -- "${FROZEN[@]}" | wc -l)" -eq "${#FROZEN[@]}"
    {
      printf '# C-5 manifest\n\n'
      printf 'Parent commit `%s`. Generated by section 2 of `docs/decisions/C5_COMMIT_2026-11-06.md`.\n' "$P"
      printf 'The C-5 commit adds this file and nothing else, so every line below also holds at the C-5 commit.\n'
      printf 'The first five lines hold all code, configuration and tests. The rest are the files of section 10 of the fold plan.\n\n'
      printf '```text\n'
      listing "$P"
      printf '```\n'
    } > "$MANIFEST"
    diff <(block < "$MANIFEST") <(listing "$P")
    echo "before: parent $P. src, configs, pyproject.toml and uv.lock equal 7bd375f's. tests equal: $(tests_same "$P"). Manifest written"
    ;;
  after)
    C5="$(git rev-parse HEAD)"
    P="$(git rev-parse "$C5^")"
    test "$(git rev-list --parents -n 1 "$C5" | wc -w)" -eq 2
    test "$(git diff --name-only --diff-filter=A "$P" "$C5")" = "$MANIFEST"
    test "$(git diff --name-only "$P" "$C5")" = "$MANIFEST"
    same_code "$C5"
    git show "$C5:$MANIFEST" | grep -qF "Parent commit \`$P\`."
    diff <(git show "$C5:$MANIFEST" | block) <(listing "$C5")
    echo "after: C-5 commit $C5 on parent $P adds only the manifest. src, configs, pyproject.toml and uv.lock equal 7bd375f's. tests equal: $(tests_same "$C5"). Manifest equals git's listing"
    ;;
  *) echo "usage: bash c5_steps.sh before|after"; exit 1 ;;
esac
```

**After the commit, in order.**

1. **Push the branch** (the coordinator). Its first push time goes to part 2, or `UNVERIFIED` if the host does not give it.
2. **Keep the commit.** It is never amended, rebased or squashed. When this branch reaches `main`, it merges with a merge commit, so the C-5
   hash stays in `main`'s history. Recommended: a tag `c-5` on it, pushed with the branch, so that deleting the branch cannot lose it.
3. **Before the fetch:** the full suite at the C-5 commit, with its output recorded (item 18). `RUN_SHA` filled in and the script's hash
   pinned. The fetch's approval entry, which names the C-5 commit (fetch plan 11.1 row 5).

**What the freeze means from then on.**

- **Every stage-one run starts from a clean clone at the C-5 commit itself:** the fetch, `--declare-costs` and the first `V0` run. So
  `code_version` names the C-5 commit in every manifest row, run row and trial row.
- **The fold plan is not edited after the commit.** Later states of section 11's parts go in the decision log and the roadmap.
- **Before any `V0` outcome,** a change to a path in the manifest means a new C-5 commit, with its own manifest, diff document and audit,
  recorded in the decision log. A root fetched at the earlier C-5 commit stays usable only if the new commit's `src/` and `configs/`
  equal the earlier one's, and the new record says so. Edits outside the manifest's paths do not touch the freeze.
- **After a `V0` outcome,** the fold plan's rule holds: a change to a rule or constant is a new dated decision and a counted trial. A

## 3. Part 3: the published diff

**How it is made.** Once the C-5 commit exists, `project-manager` runs the generator below at the top of a clean clone, with the C-5
hash: `bash c5_diff.sh <C-5 commit> > <output>`. It reads git only and contacts no host. Its output, byte for byte and with nothing
added, is committed as `docs/reviews/leak/c5_diff_<UTC date of the C-5 commit>.md`.

- **One section for each row of section 10's anchor table:** 15 sections over the 21 paths. Section 10 puts S01 to S05 in one row with three anchors, so they are split by anchor here, which gives the same diffs.
- **In each section:** the anchor, checked to be the last commit before the cut `f5bbfe1` that touched those files; the commits since, with hash, UTC time and subject and no author; `git diff --stat`; and the full `git diff` to the C-5 commit. Each block is printed under the command that made it.
- **A file with no anchor** (the cost proposal, the fold plan, `configs/engine.toml`) is diffed from git's empty tree, so the whole file is shown, as section 10 says.
- **No market value.** Every line is git output on files already committed, which rule 7 keeps free of market data. No line comes from a market root, a run folder or an output. Times are printed in UTC, so no committer's time zone appears.
- **The check.** Before its audit, `leak-auditor` runs the same generator on the same hash and compares bytes with the committed blob: `bash c5_diff.sh <C-5> | cmp - <(git show <commit>:<path>)`. Equal means nothing was written by hand.
- **The audit** is `leak-auditor`'s own text, in its own section or file, citing the document's SHA-256. It is not added to the generated document. It rules under section 10's rule, with the rulings so far applied as part 3 of the fold plan's section 11 lists. A change with no reason, or one that cites a result, is a counted trial, and the read days count as used for it.
- **When.** The audit can run beside the fetch. If it requires a change to a frozen file, the commit is made again, as section 2 says.
- **Size,** at `a2a819f` standing in for the C-5 commit: 5,090 lines and 541,183 bytes. Row 10, the gate and matrix files, is about half of it. Whether GitHub's web view renders a file that large is `UNVERIFIED`. The raw file and the generator are enough to read and check it.
- **The generator's text is fixed here, before the C-5 commit exists,** so it cannot be fitted to that commit. The C-5 commit holds this document, so the generator used is the one in that commit.

```bash
#!/usr/bin/env bash
# C-5 part 3: the published diff, from git alone. Usage: bash c5_diff.sh <C-5 commit> > <output>, run at the repository's top.
set -euo pipefail
export TZ=UTC
C5="$(git rev-parse --verify "$1^{commit}")"
EMPTY=4b825dc642cb6eb9a060e54bf8d69288fbee4904   # git's empty tree, the base for a file that is new after the cut
FENCE='~~~~~~~~'
ROWS=(                                           # fold plan section 10: <label>|<anchor, or EMPTY>|<paths>
  "Charter|38d5907|docs/00_CHARTER.md"
  "Strategy index|38d5907|docs/01_strategies/00_INDEX.md"
  "S01, S02|05cedfd|docs/01_strategies/S01_floor_pivot_rejection.md docs/01_strategies/S02_pivot_breakout_acceptance_retest.md"
  "S03, S05|42fb62b|docs/01_strategies/S03_market_structure_bos_choch.md docs/01_strategies/S05_zone_polarity_flip.md"
  "S04|d9de028|docs/01_strategies/S04_supply_demand_zones.md"
  "S06|05cedfd|docs/01_strategies/S06_liquidity_sweep_reclaim.md"
  "S07, S08|42fb62b|docs/01_strategies/S07_anchored_vwap_pullback.md docs/01_strategies/S08_volume_profile_value_area.md"
  "S09|d9de028|docs/01_strategies/S09_utc_session_range_breakout.md"
  "S10|05cedfd|docs/01_strategies/S10_volatility_compression_expansion.md"
  "Gate, matrix, triage, decision map|747a37a|docs/02_features/GATE_SPEC.md docs/02_features/STRATEGY_FEATURE_MATRIX.md docs/02_features/FEATURE_TRIAGE.md docs/02_features/DECISION_POINT_MAP.md"
  "Cost proposal|EMPTY|docs/01_strategies/COST_AND_INSTRUMENT_2026-11-05.md"
  "Fold plan|EMPTY|docs/decisions/FOLD_PLAN_2026-11-05.md"
  "configs/pipeline.toml|dafe3f2|configs/pipeline.toml"
  "configs/engine.toml|EMPTY|configs/engine.toml"
  "Portfolio outputs|0e8ee71|docs/04_PORTFOLIO_OUTPUTS.md"
)
LOG=(git log --date=format-local:%Y-%m-%dT%H:%M:%SZ --format='%h %cd %s')   # commit times in UTC, no author
block() {   # <info> <command...>: the command, then its output in one fence. A line that could close the fence stops it.
  local info="$1" text; shift
  text="$("$@")"
  if printf '%s\n' "$text" | grep -qE '^ {0,3}~{8,}'; then echo "fence clash: $*" >&2; exit 1; fi
  printf '`%s`\n\n%s %s\n%s\n%s\n\n' "$*" "$FENCE" "$info" "$text" "$FENCE"
}
printf '# C-5: the published diff, from each anchor to the C-5 commit\n\n'
printf 'C-5 commit `%s`. Made from git alone by `docs/decisions/C5_COMMIT_2026-11-06.md` section 3.\n' "$C5"
printf 'Each block is the output of the command above it. Commit times are UTC from commit headers. `%s` is git'"'"'s empty tree.\n\n' "$EMPTY"
n=0
for row in "${ROWS[@]}"; do
  n=$((n + 1))
  IFS='|' read -r label anchor paths <<<"$row"
  read -r -a files <<<"$paths"
  printf '## Row %d. %s\n\n' "$n" "$label"
  if [ "$anchor" = EMPTY ]; then
    printf 'No anchor. The file is new after the cut, so the whole file is the change.\n\n'
    block text "${LOG[@]}" "$C5" -- "${files[@]}"
    base="$EMPTY"
  else
    base="$(git rev-parse --verify "$anchor^{commit}")"
    test "$(git log -1 --format=%H f5bbfe1 -- "${files[@]}")" = "$base"   # the anchor is the last commit before the cut
    printf 'Anchor `%s`.\n\n' "$base"
    block text "${LOG[@]}" "$base..$C5" -- "${files[@]}"
  fi
  block text git diff --stat=200 "$base" "$C5" -- "${files[@]}"
  block diff git diff "$base" "$C5" -- "${files[@]}"
done
