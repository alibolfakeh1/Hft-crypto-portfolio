# Data lifecycle rulings: open questions from the data center fixes

Author: `data-steward`. Date: 2026-11-04. Branch `pipeline/first-data-run`, commit `dafe3f2`.

Answers the questions left open by the [fixes](../code/data_center_fixes_2026-11-04.md) to the
[code review](../code/data_center_2026-11-04.md): sections F-11, F-17, F-22 and F-23. For the clauses of F-22 in
questions 1 to 5, this is the entry that review asks for, saying what applies and what does not yet.

This is a reading of documents, configuration and code. Nothing was run, no source was contacted, and all sources
stay disabled, so no number below comes from a real run on an approved source. This is not a recheck of the code,
which `python-reviewer` and `leak-auditor` are doing now. Code citations are to `src/hft_crypto/data/`, except
`cli.py` and `synthetic.py`, which are in `src/hft_crypto/`.

**When things fall due:**

- **Before a source is enabled:** merged and reviewed before any source gets `enabled = true`. These do not depend on
  which source is chosen.
- **Before the first run:** set once the owner has named a source, before the first run that can fetch from it.
- **Later:** at the trigger named in the row.

## 2. Conditions for real deletion in the workflow (question 3)

All of these, before `--execute` goes in `.github/workflows/daily-pipeline.yml`:

1. `python-reviewer` has returned `PASS` or `PASS WITH CONDITIONS` on the recheck of F-01, F-02 and F-11, with no
   condition open on those three, and `project-manager` has recorded it.
2. R3.1, R3.3, R3.4, R3.5, R4.1, R4.2 and R7.1 are merged and reviewed.
3. A reviewed rule exists that frees cache space. On GitHub that can only be `curated-trades-window`, with R8.1 to R8.4
   done. `raw-archive-after-curated` is not a reason, because it runs inside `ingest`.
4. `run_log/deletions.jsonl` has been seen on the `results` branch after a run. The catalog lives in the cache, so the
   published log is the only copy after a lost cache.
5. I have reviewed at least 7 consecutive scheduled dry run plans on the approved source, and also the first plan in
   which the rule selects a file. For a 90-day window that comes 90 days after the first files at the earliest. Each
   item has the expected class, rule, size and reason, and none is outside the rule's zone.
6. R3.6 is ready, and the change goes through a pull request with `python-reviewer`.
